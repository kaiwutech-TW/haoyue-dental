# 主持人觀察表使用方式

開始前記下部署版本與日期，確認是新會話、模型來源與預算狀態正常。若規則模式／服務不可用，明確記錄，不能拿它代替模型版驗證。

先讓參與者自行探索；卡住時先問「你現在預期會發生什麼？」再決定是否提示。每次提示都記錄內容及時間。不要讓他們照既定句子念完，然後把成功視為自然語言泛化能力。

記錄：開始、首次正確說出用途、送出需求、看到時段、確認前判斷、點確認、找到已儲存結果、重載後找到結果。每項使用相對秒數，不必記私人身份。

任務結果分類：未提示成功／提示後成功／失敗／中止／未測。確認前與確認後的理解分開記。系統選錯意圖但使用者發現並修正，不算首次正確完成。

完成後再問原因與偏好。最後請參與者說明「何時真的改了預約」與「轉人工是否表示已有真人回覆」，核對其理解，不只問滿不滿意。

公開報告只使用同意公開的匿名摘要。原始筆記與錄影放在忽略的 `artifacts/private/pilot/`，不要放進 public repo。將結果填到 `results-template.md` 的副本；預設空表不算測試完成。
