# 牙醫櫃台／店家訪談與原型測試

先說明這是行政原型，沒有對接真實患者或診所排程，不提供診療判斷。請用匿名、概括的例子，不開啟或傳送真實病歷、患者訊息或價目機密。

## 展示前：問已發生的事

- 最近一次患者想改期，你們怎麼處理？經過哪些步驟、由誰負責？
- 最近一次說法反覆、家屬代約、重複訊息或時段衝突，是怎麼發現與收尾的？
- 哪些訊息最常見？請分清實際記錄、粗估與不知道。
- 現有 LINE、電話、預約表單或診所系統哪裡已經做得夠好？什麼情況必須真人？
- 哪類錯誤最不能接受？若發生，誰發現、誰修正？

## 測試：請對方自己操作

使用 `user-tasks.md` 的改期與人工接手任務，再請櫃台提出兩個自己遇過的行政情境，用合成資料重述。記錄系統能否正確完成、澄清或轉接；不要現場替模型修正輸入卻把結果算成功。

請對方說明：要採用還缺哪一段？若診所行事曆已另有系統，誰是最後的排程來源？忙碌時誰看交接、多久能處理？

## 展示後：測試承諾而非禮貌

- 願意安排下一次試用嗎？由誰參與、什麼時候、用哪個具體流程？
- 願意以什麼現行工作結果作比較？如何量時間、人工介入與錯誤？
- 若要談付費試點，誰能決定？需要哪些成果與維護安排？目前有沒有替代支出？

不要從一句「不錯、可以賣」推論付費意願。未確認的價格、採用率與節省工時不寫成成果。
