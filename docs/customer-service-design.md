# 客服設計與資料使用邊界

使用者提供的客服工作簿以本機唯讀方式檢閱；公開專案不包含原始工作簿、真實診所價格、患者名單或客服報表。沒有把這批資料上傳到 Nebius、Tavily 或 Colab，也沒有把它們算成此次 NVIDIA 微調語料。

可通用的設計原則已落地：先辨識需求，再詢問必要條件，最後給可操作的下一步；不確定的診所事實不猜測；真人接手要有案件與回覆狀態，不能只說「已為您轉接」卻沒有執行。

## 文字與按鈕

按鈕只是輸入捷徑。自由文字與快捷按鈕都進入相同 `chat` 服務、NVIDIA 八類意圖、規則驗證與確認交易。中文與英文各有會話 cookie 和展示文案；患者資料仍為共享合成資料。英文冒煙測試的完整結果在 `reports/english-demo-smoke.json`，不是獨立保留集。

## 耐心而不貼標籤

- 「按錯／不會用」等明確文字得到一步一步的操作提示；不猜測使用者年齡。
- 60 秒內重複相同文字保留目前時段／確認卡，回覆耐心說明，跳過再次模型呼叫。不同文字仍是新需求，撤銷舊確認。
- 明確擔心或挫折用詞可觸發支持性的前綴。這是高精度詞語規則，並非真實情緒判定、心理分析或已訓練的情緒模型。反諷、否定與複雜上下文可能誤觸，不能據此作重要決策。
- 症狀、真人請求、家人代辦仍優先交接。語氣提示不能跳過安全與身分檢查。

## 何時才需要再訓練

目前 adapter 保持 v2，不為了 UI 翻譯或規則說明重跑訓練。若擴展成 intent＋support 多任務決策，先建立去識別且授權可用的語料、明確情緒標註定義與標註者一致性，再以預先固定的保留集比較：意圖品質是否退步、否定句是否誤判、低信心是否能拒答。不可把現在的八意圖權重描述成情緒微調。
